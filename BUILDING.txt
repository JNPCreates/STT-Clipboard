STT Clipboard source and build instructions
==========================================

Run the source
--------------
Use 64-bit Python 3.10 on Windows (the tested version). In PowerShell:

py -3.10 -m venv .venv
.\.venv\Scripts\python.exe -m pip install pip==26.3
.\.venv\Scripts\python.exe -m pip install torch==2.8.0 --index-url https://download.pytorch.org/whl/cu126
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe STT_to_clipboard.py

The GPU build uses a compatible NVIDIA GPU/driver; it falls back to CPU otherwise.
The app does not need FFmpeg for its microphone recordings.

Build the executable and source ZIPs
-----------------------------------
Run "Build STT Clipboard.cmd" --zip, or:
.\.venv\Scripts\python.exe build_exe.py --zip

This creates a NEW release under dist\<timestamp>-gpu, with Windows ZIPs, a
minimal source ZIP, and SHA256SUMS.txt. Large builds are split into ordinary ZIPs
below GitHub's 2 GiB per-file limit; extract all parts into the same folder.
Models are NOT bundled or downloaded by
the build. At runtime the selected model downloads when first needed and is
reused from %USERPROFILE%\.cache\whisper (or XDG_CACHE_HOME\whisper if set).
Standard recording downloads after Stop; real-time downloads before recording.

The Windows ZIP includes Python, GPU libraries, UI assets, and dependency notices.
Extract the complete ZIP and launch STT_Clipboard.exe. Keep _internal and licenses
beside it. No Python installation is required on the receiving computer.
GPU runtime libraries still make the app download sizable even without models.

Public builds exclude personal settings and transcription history. For your own
installation only, --personal copies those files; do not distribute that build.
Earlier builds may already contain personal data: create a new public build.
Nothing overwrites your existing releases or your original installed application.

Build logs and dependency versions are under build\<timestamp>-gpu. The build
environment uses junctions into installed packages; do not recursively follow
those junctions when cleaning it. STT_PYTHON can select another Python executable.

Tests
-----
.\.venv\Scripts\python.exe -m unittest test_speech_engine test_model_settings test_audio_input

On a second PC, try recording/pasting, microphone selection, mute/unmute with the
QUIET indicator, a first model download, real-time for over a minute, and history
after restarting. Models require internet only for their initial download.

Storage
-------
Settings and transcription history are JSON files beside the app. Use a writable
folder. History defaults to 10 entries and can be set to 1-1000. Lowering the
limit removes older entries. No audio files are saved. A failed standard recording
can be retried from Settings while it is still held in memory; closing the app
discards it. The meter measures input volume, not speech recognition quality.

Publishing
----------
Use the source ZIP's contents for the repository and the Windows ZIPs for the
release download. Source archives contain only an explicit list of app/build/test
files and small assets, excluding .env, personal JSON, backups, models and builds.
Keep the MIT license and bundled third-party notices. Publishing is manual.
